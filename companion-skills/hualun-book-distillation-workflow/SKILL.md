### 验证记录

- **验证时间**：2026-04-12
- **验证书籍**：曼昆《经济学原理》微观分册（micro_text.txt）
- **验证结论**：格式可行，三张表（章节结构/类比库/误区库）均可从PDF提取

### 下载前确认规则（强制）

同一主题可能有多本不同方向的书（如"控制论"有维纳原著、钱学森工程控制论、现代控制理论）。**下载前必须列出选项让用户确认方向**，不要自行选择后直接下载。

**优先中文版**：用户要求所有书籍默认优先中文版，不用每次询问。

### 执行步骤

#### Step 1: 提取全文字

```python
import pdfplumber
import glob
import os

# ⚠️ 必须用 glob.glob(recursive=True) 递归搜索，不要硬编码路径
# 递归搜索 ~/Downloads/ 下所有子目录（含中文路径、空格、特殊字符的书名）
pdf_files = glob.glob(os.path.expanduser("~/Downloads/书籍/**/*.pdf"), recursive=True)
path = pdf_files[0]  # glob 返回的第一个匹配

with pdfplumber.open(path) as pdf:
    text = ""
    for page in pdf.pages:
        t = page.extract_text()
        if t:
            text += t + "\n"
```

**关键经验**：书名含 `Anna's Archive`（弯引号 `'`）或长路径时，`open(path)` 直接写路径会失败。必须用 `glob.glob()` 绕过编码问题。

**pdfplumber 读不出字 / 报 ModuleNotFoundError / 大体积 PDF（>10MB 或 >300 页）**：改用本 Skill 自带的 PyMuPDF 兜底脚本 `scripts/pdftext_extract.py <pdf路径> [输出路径]`（缺库先 `pip3 install --quiet pymupdf`），输出带 `=== PAGE N ===` 页码分隔的全文，便于类比库注页码。（2026-09-28 由已归档的 hualun-textbook-distillation 并入）

**扫描版 PDF 处理**：当 `extract_text()` 返回空或极短文本时，切换到 OCR 流程（见 `hualun-ai-learning-accelerator/references/ocr-pdf-extraction.md`）。

#### Step 2: 生成三张表（核心规则）

**执行原则：单次 call 完成一章，不循环调用 API。**

用 regex + 字符串匹配在提取好的全文字上离线提取，速度快且无 API 限制。

**概念词提取规则（新增 2026-04-13，大哥提出）：**

```
① 书里章节/小节标题已有的概念词 → 直接提取，不造新词
② 书里没有概念词、只有句子描述的 → 搜索该领域的通识概念词
   （维基百科/教材前言/术语表里一定找得到，不是自己发明）
③ 实在找不到通识概念的 → 保留原句，标记"待定概念"
④ 核心原则：绝不自行发明概念标签；自己造的概念市面不通，他人不懂
```

**按需蒸馏**：调用方指定要蒸馏哪一章，一次只跑一章。21章不需要一次跑完。

**{NN}-类比库.md** — 识别特征：
- "就像"、"如同"、"设想"
- 具体人物/场景（乔丹剪草坪、飞机卖票）
- 用 `grep -i` 扫描关键词验证

**类比库质量门（借鉴仓颉.Skill）**：找到候选类比后，收录前必须通过：
- ✅ 这个类比是在解释本章的核心概念（不是装饰性的文学修辞）
- ✅ 类比和概念之间的映射关系清晰（能用一句话说清"A对应B"）
- ❌ 跳过：泛泛的比喻、与本章概念无直接关系的举例

**{NN}-误区库.md** — 识别特征：
- "学生经常错误地认为"
- "不要把X和Y混淆"
- "重要的是要记住"
- "你可能认为…但实际上"
- "常见的误解是"

**误区库三重验证门（借鉴仓颉.Skill，收录前必须全部通过）**：
- **V1 文本支撑**：书中至少有2处独立段落支撑这个误区（或有完整论证，非一句带过）
- **V2 非显然性**：这个误区不是所有受过教育的人都知道的常识
- **V3 章节相关性**：这个误区直接对应本章的核心概念，不是边缘话题

通不过三重验证的候选 → 降级为"补充引用"，不作为独立误区条目收录

**{NN}-章节结构.md** — **子项确定规则（强制）**：

1. **子项 = 书里实际的中节编号**（如 3.1、3.2、3.3……）
   - 该章节有中节编号？→ 以中节为子项
   - 无中节但有小节编号？→ 以小节为子项
2. **禁止用学习目标列表（"在本章中你将——"）作为子项来源**
   - 学习目标列表仅作教学前的预习参考
3. **必须进入每章正文**，提取所有小节编号作为子项
   - 不得只从目录页摘要提取，必须逐章扫描正文中的编号结构
4. **数量词校验**：
   - 若章节名含显式数量词（如"十大原理"），校验子项数量是否与数量词匹配
   - 不匹配 → 标记⚠️ + 重新提取（最多3次）

### 按需单章蒸馏原则

**不要全量蒸馏整本书**。正确做法：

1. 只蒸馏当前需要教学的那一章
2. 立即开始教学，不等待后续章节
3. 教到第N章时，后台预取第N+1章
4. 永远只蒸馏你已经教到或即将教的那一章

全量蒸馏的坏处：阻塞用户等待、API错误时进退两难、用户感知不到价值。

### PDF文字提取实战规律（曼昆微观分册实测）

以下规律基于曼昆《经济学原理》第7版微观分册 PDF（pdfplumber提取）：

**子项提取**：

**⚠️ 章节名含显式数量词时，数量词优先级高于学习目标列表：**

若章节名含"十大原理"/"五大要素"/"N个步骤"等数量词：
1. **定位正文中的编号列表**（原理一～十 / 五大要素 / N个……），不是学习目标列表
2. 数量词校验：子项数量必须与数量词精确匹配（如"十大"→ 10条）
3. 不匹配 → 标记⚠️ + 重新扫描本章正文的编号结构（最多3次）

**子项编号提取规律**：

⚠️ **数量词章节（含"十大原理"等显式数量词）**：直接提取正文编号列表（如"原理一"到"原理十"），数量词校验自动满足。

**其他章节（无显式数量词）**：按中节编号提取（如3.1、3.2、3.3）。

**⚠️ 注意**：所有章节的子项来源均是正文的编号结构，**不是学习目标列表**。学习目标列表（"在本章中你将——"）仅作预习参考。

**类比提取**：
- 关键词：`就像`、`如同`、`设想`、`设想你`、`如果你`
- 曼昆最常用的具体类比：乔丹剪草坪、飞机卖票、农民与牧牛人

**误区提取**：
- 曼昆在正文中通常没有显式"学生错误"框，但每章"问即答"前的总结段落会点出常见误解
- 搜索`"不要把"`、`"你可能认为……但实际上"`、`"常见的误解"`等触发词

### 输出目录结构

**文件命名规则（强制）**：蒸第 `{NN}` 章 → 必须同时生成以下3个文件：
```
~/.hermes/learning/[领域名]/materials/
├── {NN}-章节结构.md   ← 章节编号必须与章号一致
├── {NN}-类比库.md     ← 同上
└── {NN}-误区库.md     ← 同上
```
- 三个文件**同时生成**，缺一不可
- 禁止把A章内容写进B章编号的文件
- 禁止只写一个文件就报"完成"

**调用示例（蒸馏第三章）**：
- 章节结构 → `03-章节结构.md`
- 类比库 → `03-类比库.md`
- 误区库 → `03-误区库.md`

**⚠️ 不得覆盖已有文件**：执行前先检查目标文件是否存在：
- 若文件存在 → 读取内容，确认里面只有蒸馏目标章节；若混入其他章节 → 拆分或重新蒸馏
- 若文件不存在 → 正常写入
- 主 Agent 在调用本 workflow 前，必须先确认目标章节编号

```markdown
# [书名] 类比库

## 第{NN}章 [章名]       ← NN 和章名从教材中提取
| # | 类比内容 | 页/段 | 说明概念 | 映射关系 |
|---|---------|-------|---------|---------|
| 1 | 原文引用 | | 概念名 | A对应B |
```

```markdown
# [书名] 误区库

## 第{NN}章 [章名]       ← NN 和章名从教材中提取
| # | 学生误解 | 作者纠正（原文）| 层次 | V1-V2-V3 |
|---|---------|----------------|------|----------|
| 1 | 误解内容 | 原文纠正 | 框架/领域 | ✅✅✅ |
```

> `V1-V2-V3` 列标注三重验证结果，三个✅才收录；否则注明降级为"引用"。

```markdown
# [书名] 章节结构

## 第{NN}章 [章名]
| 子项 | 核心概念 | 标准定义（原文） | 大白话 | 边界/局限 |
|-----|---------|----------------|-------|---------|
| 3.1 | 概念名 | 书中原文 | 一句话 | 作者未覆盖/该理论失效的场景 |
```

> `边界/局限` 列（借鉴仓颉.Skill B维度）：记录作者视角的盲点、理论失效场景。
> 这列直接喂给 hualun-ai-learning-accelerator 的苏格拉底追问步骤，帮AI出反例题。

> **写入前必查**：目标文件是否已存在且含其他章节内容？若有，先读取并确认不混用，再写入。

## 找书与下载（唯一顺序）

本节是找书顺序的唯一真源；hualun-ai-learning-accelerator 只引用这里，不另写一套。

1. 同一主题有多个方向/版本 → 先列选项让用户选，不自行下载；默认中文版，不用问。
2. 已配置 `WEREAD_API_KEY` → 先用微信读书找书、取章节目录做学习骨架（只拿到目录时，教学方须说明不是逐页原文）。
3. 本地教材目录 `~/Downloads/书籍/`（递归搜索子目录）。
4. 公版渠道：Project Gutenberg → archive.org。
5. 电子书宝库（见 hualun-ai-learning-accelerator 的 `references/ebook-treasure-chest-integration.md`）。
6. **失败重试上限**：以上都没找到或下载失败时，最多再换 **2 种**别的方式尝试（例如换中文名/英文原名/作者名/ISBN 重搜，换同一渠道的其他格式或下载链接，或改用浏览器手动下载）。2 次仍不行就停，告诉用户试过哪些，请用户提供文件（飞书发送或放进教材目录）。
7. 非公版/版权教材不从随机 PDF 站、网盘镜像、可疑目录硬扒；优先用户自有文件或微信读书骨架。

下载保存到 `~/Downloads/书籍/[学科名]/`。命令行下载常失败时可改用浏览器手动下载（算作一次换方式）。

## 主 Agent 调用说明

本 workflow 设计为由 `hualun-ai-learning-accelerator` skill 在教学前自动调用。

**调用流程（主 Agent 必须执行）：**

```
① 用户说「开始学习」/ 「继续学习」
   ↓
② hualun-ai-learning-accelerator 检查 ~/.hermes/learning/[领域名]/materials/ 下是否有 {NN}-章节结构.md + {NN}-类比库.md + {NN}-误区库.md
   ├─ 三个文件都存在 → 跳过蒸馏，直接开始教学
   └─ 缺任意一个 → 触发 hualun-book-distillation-workflow，执行教材蒸馏
   ↓
③ 蒸馏完成后，主 Agent 读取生成的三个文件，开始费曼四步教学
```

**关键原则**：
- 蒸馏是**教前准备**，不是独立操作。主 Agent 不得跳过蒸馏直接用自己的常识讲课。
- 蒸馏遇到 API 错误时，主 Agent 必须静默重试，不向用户报错。
- 蒸馏完成后，主 Agent 必须读取文件内容并用于教学输出，不得束之高阁。
