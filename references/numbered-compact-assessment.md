# 编号极简答案判定与章节收尾

适用场景：学习流程中，用户用极短格式回答当前考核题，例如 `1 小 2买方 3上升`、`1A 2错 3需求下降`。

## 处理规则

1. **先绑定当前题**：默认这是最近一道小节/章节考核题的答案，不要跨上下文解释成旧任务选项。
2. **解析编号**：按 `1/2/3` 或 `A/B/C` 提取答案，允许用户省略标点和解释。
3. **逐项判定**：逐项对照题目要求，给出简短反馈：对在哪里；若错，指出关键误区。
4. **全对时立即收尾**：
   - 小节题全对：更新 `state.md` + 轻量 `section-notes/`，进入下一最小子项。
   - 章节综合题全对：先标记章节 ✅，加入 1/7/30 天复习队列，再写 Obsidian 章节笔记和学习首页。
5. **输出节奏**：不要长篇汇报路径；只说“已记录到学习进度/Obsidian”，除非用户追问或需要排查。

## 章节收尾核对清单

章节综合题全对后，不要只写一篇笔记就结束，必须核对：

- [ ] `state.md`：当前位置、节点状态、已掌握概念、复习队列已更新。
- [ ] `section-notes/`：当前小节/章节通过有轻量记录。
- [ ] Obsidian 学习笔记：章节核心概念、误区、考核记录已写入。
- [ ] `LLM Wiki/wiki/学习/AI学习/00-入口.md`：当前课题、进度、下一次复习已同步。
- [ ] 若 skill 当前版本要求章节知识卡/思维导图：生成并发送/保存；不要漏掉视觉资产。

## 示例

用户：`1 小 2买方 3上升`

回应结构：

```text
对，大哥，这题过了：
1. 需求弹性小……
2. 买方承担更多……
3. 总收入更可能上升……

已记录到学习进度和 Obsidian。下一次可以进入第X章。
```
