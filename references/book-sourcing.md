## 找书顺序（以 hualun-book-distillation-workflow 为准）

找书与下载的唯一顺序、失败重试上限（最多再换 2 种方式）、版权边界，都写在 `hualun-book-distillation-workflow` 的「找书与下载（唯一顺序）」一节。本页下文各处出现的顺序如有出入，一律按那里。

### 下载书籍强制规则

**同一本书有多个方向/版本时，必须先问用户再下载。** 不要自作主张下载一个版本。

示例：用户说"控制论"，有维纳原著、钱学森工程控制论、现代控制理论等方向 → 必须先列出让用户选择，不要直接下载其中一个。

**下载必须按 hualun-book-distillation-workflow「找书与下载（唯一顺序）」走。**

**禁止跳过步骤直接搜其他网站。**

【联网与外部材料教学模式】（应对前沿技术、无标准教材的领域）

触发条件：用户要求学习的主题在微信读书和本地教材库中均无系统教材（如：GraphRAG、LangChain、AI Agent 架构等）。

**核心机制：** Skill 自动化身"资料整理师"+"课程架构师"，将零散素材重组为结构化的章节表。

分支 A：你提供材料（URL / GitHub 链接 / 文档地址）
    ① 抓取与清洗：访问链接提取 Markdown/正文，自动清除广告、侧边栏和无关干扰。
    ② 智能大纲构建：根据文章内容的内在逻辑，合并重复知识点，拆分为循序渐进的【小节大纲】（写入 `materials/{NN}-课程大纲.md`）。
    ③ 实时备课：针对每个知识点生成大白话类比和易错误区，并存入对应 `materials` 文件。
    ④ 教学执行：按照这个临时生成的"专属教材"一步步带你学。

分支 B：我去帮你找材料（自主建课）
    ① 边界设定：明确学习目标（入门原理/进阶实战）、时长偏好。
    ② 全网精选：使用网络搜索该领域的 Top 3-5 篇高质量资源（官方文档 > 知名技术博客 > 优质专栏）。
    ③ 过滤与评分：剔除过时、灌水、广告多的内容；选取证据链最完整的一批。
    ④ 同分支 A（步骤②-④）：重组大纲 → 实时备课 → 生成 Obsidian 学习笔记。

硬性规定（联网模式）：
- ❌ 严禁一次性把整章内容倒给学生。即使是网文，也要人工切片成 20 分钟能学完的子项。
- ✅ 每一节课结束必须产出一份极简 Obsidian 笔记：`学习笔记/领域名-{章节名}.md`。
- ✅ 每一节课结束时必须进行"苏格拉底追问"，确保不是光看懂了文字而是理解了逻辑。
```

### 后续流程（选完书籍后）

**硬规则：新书学习必须先走微信读书找书 → 建中文骨架 → 蒸馏知识地图。**
只要 `WEREAD_API_KEY` 可用，就不要先查本地 PDF、不要直接凭书名开讲。微信读书找不到/目录不可用/用户要求严格逐页原文时，才回退本地教材蒸馏。

**⚠️ 下载书籍前必须先问用户想学哪个方向/版本，不要自行决定下载。**（用户纠正：2026-05-26）

```
① 【优先微信读书建骨架 + 蒸馏知识地图】
   若已配置 `WEREAD_API_KEY`：
   1. 调微信读书 `/store/search` 确认目标书籍 bookId（注意搜索结果在 `results[].books[].bookInfo`，不是顶层 `books`；顶层为空不代表没搜到）
   2. 调 `/book/info` 获取中文书名、作者、简介、分类、评分等基础信息

   4. 基于章节目录初始化 `state.md` 的知识地图初稿：章节/大节/小节节点、当前进度、复习队列占位

   ├─ 找到书与章节骨架 → 进入②
   └─ 找不到书/章节信息不可用 → 进入「本地教材回退」

   └─ 用户没有微信读书 → 进入「本地教材回退」

**禁止**：在任何步骤解释工作流、重复确认偏好、告知考核节奏。


## 子项确定规则（强制）

子项 = 书里实际的中节编号（3.1 / 3.2 / 3.3……）

```
该章节有中节编号？
  ├─ 有 → 以中节为子项
  └─ 无中节但有小节编号 → 以小节为子项
```

**禁止**：
- ❌ 用学习目标列表作为子项来源
- ❌ 自行推断数量或编造子项
- ❌ 看到n条就说"本章有n个子项"，必须从正文小节标题提取


## 知识地图

由 `hualun-book-distillation-workflow` 从本地书籍动态生成，存入 `state.md`，**不在 skill 里硬编码**。

格式见 `state.md` 的「节点状态」和「复习队列」章节。


## 教材蒸馏

依赖 `hualun-book-distillation-workflow 2.8`（必须 >= 2.8）。

初始化新领域时，优先从 `~/Downloads/书籍/[学科名]/` 查找书籍；多个文件时列出让用户确认路径。

```
输入：本地PDF书籍
输出：类比库（每章类比）/ 误区库（显式纠正的误解）/ 章节依赖结构
```

### 蒸馏可靠性四规则（对抗「蒸馏有损」）

蒸馏必然有损（丢论证过程、代码细节）。四条规则把损失变成可控特性，而不是隐患：

1. **原文留档（强制）**：蒸馏的同时，把原始材料完整存进 `~/.hermes/learning/<主题>/materials/<资料名>/raw/`，作为 Hermes 学习运行真源。原文是事实源，三件套只是地图，缺细节回 raw 查原文。
2. **流程兜底（强制）**：概念层信三件套，动手/源码层必须回原文。教学时明确区分「蒸馏有」和「蒸馏没有」，后者不得凭印象编造。
3. **证据列（三件套格式）**：每个条目除大白话外强制保留原文列——章节结构「标准定义（原文）」、类比库「原文类比/补充类比」、误区库「作者纠正（原文）」；论证链长时加「为什么这样设计」列抓作者关键推理。
4. **原文映射表（大纲格式）**：`{NN}-课程大纲.md` 里每个概念标「原文出处 raw/第X篇」，标清哪里信蒸馏、哪里必须回原文。

若用户明确要求长期共享、保存或供其他 Agent 使用，外部原件通过 Capture 保留，由小助手归类到实际学科；先查迁移映射和来源索引，已有原件只关联，不重复复制。Wiki 同时接纳标明来源的教材参考与个人学习笔记，不要求所有内容都是稳定结论。原始教材与蒸馏运行真源仍在本地学习目录。


### 预取机制

学完第N章后，后台触发第N+1章蒸馏。

**蒸馏文件命名规则（强制）**

> 蒸第 `{NN}` 章 → 必须同时生成且只生成：
> ```
> materials/{NN}-章节结构.md
> materials/{NN}-类比库.md
> materials/{NN}-误区库.md
> ```
> - 三个文件同时生成，缺一不可
> - 文件名 `{NN}` 必须与章节编号一致
> - **绝对不允许**：把A章内容写进B章编号文件，或只写一个文件就说"完成了"

**预检（蒸馏前必做）**：
```
要蒸馏第{N+1}章
  ↓
检查三个文件是否存在
  ├─ 都不存在 → 正常蒸馏
  ├─ 存在但内容不是第{N+1}章 → 先删除/标记为旧版，再蒸馏
  └─ 存在且内容正确 → 跳过（已就绪）
```

**静默降速重试**：遇到 API 429/529 时，指数 backoff（30s→60s→120s），不打扰用户，不提供跳过选项。3次重试仍失败 → 记录状态为「🔄 预取中」，继续教学。

**单次 call 原则**：单章用单次 API call 完成，不循环调用。

**蒸馏后验证（强制）**：

```
① 检查文件数量：应有3个文件
   └─ 缺文件 → 立即重蒸馏
② 检查每个文件内的 ## 第X章 标题与编号是否匹配
   └─ 不匹配 → 立即重蒸馏
③ 检查文件内容是否混入了其他章节
   └─ 发现多个 ## 第X章 在同一文件 → 拆分/重蒸馏
④ 全部通过 → 完成，继续教学
```

**验证失败不通知用户**：自行重蒸馏，不向用户报错。
