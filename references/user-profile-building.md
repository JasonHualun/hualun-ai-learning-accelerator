# 用户学情档案构建流程

## 触发时机

开始新学科前，检查 `~/.hermes/learning/user-profile.md` 是否存在：
- 不存在 → 构建学情档案
- 存在 → 读取档案，根据已学领域判断基础水平

## 构建步骤

### 1. 从微信读书获取阅读数据

调用 `/shelf/sync` 获取书架数据：
- `books[]`：所有电子书
- `books[].finishReading`：已读完的书
- `archive[]`：书单分类

### 2. 分析知识领域

按 `books[].category` 统计分类数量，识别：
- **强项领域**：读得多的分类
- **待拓展领域**：读得少或没有的分类

### 3. 提取已读完书籍

筛选 `finishReading == 1` 的书籍，作为用户知识背景的依据。

### 4. 生成用户学情档案

文件路径：`~/.hermes/learning/user-profile.md`

```markdown
# 用户学情档案
更新：YYYY-MM-DD

## 基本信息
- 微信读书 API Key: 已配置
- 书架总量：X 本
- 已读完：Y 本
- 书单分类：...

## 阅读偏好（按分类统计）
1. 分类A: N 本
2. 分类B: M 本
...

## 已读完书籍（Y 本）
1. 书名 - 作者 [分类]
...

## 知识领域分析
### 强项领域（读得多）
- ...

### 待拓展领域
- ...

## 学习偏好（待观察）
- 节奏偏好：待观察
- 理解风格：待观察
- 容易卡住的地方：待观察

## 反应模式（实时更新）
| 触发词 | 含义 | 教学调整 |
|--------|------|---------|
| "太简单/跳过/会了/上过了" | 水平比预估高 | 立即跳过，标记已掌握 |
| "太难/听不懂/等等/没理解" | 跟不上 | 换类比，降速，拆更细 |
| "为什么/凭什么/怎么来的" | 要求深层解释 | 给原理，不接受表面答案 |
| 沉默 / 只说"嗯" | 可能没懂 | 主动追问确认 |
```

## 教学中的应用

1. **选择类比**：根据用户已读完的书籍，选择用户熟悉的领域做类比
2. **判断基础**：如果用户在相关领域有阅读背景，可以加快节奏
3. **发散教学**：根据用户阅读偏好，主动关联用户感兴趣的领域

## 注意事项

- 书架 ≠ 已读完。书架是收藏的书，已读完是真正读完的书
- 分类统计仅作参考，不代表用户真正理解该领域
- 学习偏好需要在教学过程中实时观察和更新
- 反应模式需要在教学过程中实时记录
