# 状态文件、学情档案与复习

> 由 SKILL.md 3.0.1 原文整段迁出（2026-09-28 压缩），规则原样保留；冲突处已按主 SKILL.md 统一。

## 状态文件

### 存放位置

```
~/.hermes/learning/[领域名]/state.md
```

### 触发写入（事件驱动）

| 触发时机 | 写入内容 |
|---------|---------|
| 子项完成（四步+小节考核通过后） | 立即更新「已覆盖子项」|
| 章节综合考核通过 | 节点状态✅ + 加入复习队列 |
| 误区被识别 | 追加误区记录 |
| 复习完成 | 更新队列该条 |
| 复习失败 | 标记 ⚠️ 或给补做机会 |
| 当前位置变化 | 更新当前位置段落 |

**关键原则：子项完成后立即写入，不等整章结束，不等用户提醒。**

### state.md 格式

```markdown
# 学习状态 - [领域名]
更新：YYYY-MM-DD

## 元信息
领域：[领域名]
源书路径：[具体文件路径]

## 当前位置
节点：第X章 [名称]
阶段：费曼第N步
已覆盖子项：[子项1] → [子项2] → [当前]

## 节点状态
| 节点 | 状态 | 通过日期 | 备注 |
|------|------|---------|------|
| 第一章 | ✅ | YYYY-MM-DD | |
| 第二章 | 🔄 | — | 费曼第二步 |

## 复习队列
| 到期日 | 节点 | 类型 | 状态 |
|--------|------|------|------|
| YYYY-MM-DD | 第一章 | 7天-反例 | 🔄 |

## 误区记录
- [日期] 章节-层：误区描述
```

### 节点四态

| 符号 | 含义 |
|------|------|
| ❌ | 未开始 |
| 🔄 | 学习中 |
| ⚠️ | 考核未通过/复习失败，需重学 |
| ✅ | 已过关 |


## 用户学情档案（跨学科）

**文件路径**：`~/.hermes/learning/user-profile.md`

每次开始新学科前，必须读取此文件。教学过程中根据用户反应词实时更新。

### 档案结构

标准模板见 `references/user-profile-template.md`（学习偏好 / 已学学科表 / 反应模式表）。

### 学情判断规则

1. 开始新学科时：读取 user-profile.md → 有该学科记录则按已知水平继续；无记录则标记"新学科"
2. 教学过程中：用户说"太简单/跳过/会了" → 立即标记已掌握，进下一子项
3. 教学过程中：用户说"太难/听不懂" → 换类比重新讲，降速
4. 教学过程中：用户说"为什么/凭什么" → 给深层原理，不接受笼统说法
5. 每次子项完成后：更新 user-profile.md 的已学学科表

### 微信读书集成（可选）

如果 `WEREAD_API_KEY` 已配置，开始新学科时可调用微信读书 `/shelf/sync` 获取用户已读书籍，自动填充「已学学科」表。API 调用方式见 `weread-knowledge-integration` skill。


## 入口诊断

```
"你现在对这个领域知道什么？说出来。"
    ↓
学生回答
    ↓
├─ state.md 已有 ✅ 节点 → 说出那些节点名，问"这些你都懂吗"
│   ├─ 懂 → 跳过，进入下一未完成节点
│   └─ 不懂 → 从对应节点开始
│
├─ 没有记录但声称懂 → 出1道迁移题验证
│   ├─ 通过 → 标记 ✅，跳过
│   └─ 不通过 → 从该节点开始
│
└─ 完全空白 / 有错误直觉 → 从最基础或对应节点开始
        将学生说的错误内容映射到知识地图具体章节，从那里开始
```


## 复习队列

间隔：1天（迁移题）/ 7天（反例题）/ 30天（迁移题）

### 触发时机

1. 每次 session 开始时，检查复习队列。日期从系统消息获取，不要猜。
2. 复习提醒 cron 只推「授权清单」内的章节（见下节）；复习队列本身仍以 state.md 为事实源，答完的题两处都要销账。

### 复习定时提醒（授权清单制，默认关闭）

**核心原则：默认不提醒。** cron 不扫复习队列、不自动推送任何章节。只有用户在学习会话里明确同意开启的章节才进授权清单。

- 脚本：`~/.hermes/scripts/ai-learning-review-reminder.py`（no_agent watchdog，cron job「AI学习每日复习提醒」每天 08:00）
- 授权清单：`~/.hermes/learning/review-opt-in.json`
- 间隔：1天（迁移）/ 7天（反例）/ 30天（迁移），开启当天起算
- 推送：飞书 AI 学习群 + Google 日历事件；同一天同一项只推一次；无到期项静默

**学完一章后的询问话术（必须问，用户要求）：**

> 「这章要不要开启定时复习提醒？（1/7/30 天各一道复习题）」

- 用户同意 → 执行：`python3 ~/.hermes/scripts/ai-learning-review-reminder.py --enable <课程名> <章节节点名>`
- 用户拒绝 → 什么都不做，不再提
- 复习答完销账 → `--complete <课程> <节点> <类型>`（三轮全完成自动移出清单）
- 用户中途反悔 → `--disable <课程> <节点>` 全部取消
- 查看当前清单 → `--list`

### 到期处理

```
读取 state.md → 找到期日 ≤ 今天的条目
    ↓
若来自 cron/定时复习提醒：先列到期项，问是否现在开始；不要直接出题或开讲
    ↓
用户说“都会了/都复习过了/直接记录复习过了”
    ├─ 直接将对应到期项标记 ✅，写入 state.md + Obsidian 学习首页
    └─ 备注“用户确认已会/已复习”，不强行补考
    ↓
用户明确要开始复习 → 出对应类型复习题
    ↓
用户回答后先判定答案
    ├─ 正确 → 简短确认 + 更新复习队列为 ✅ + 继续下一学习节点
    └─ 错误/模糊 → 当场补做一次
补做再失败 → 节点改为 ⚠️，下次重走费曼四步
```

**交互约束**：复习题答对或用户确认“都会了”后，不要长篇汇报内部文件操作、不要列一堆路径打断学习节奏。若写入了 `state.md` 或材料文件，只用一句话透明说明“已记录到学习进度”，然后立刻进入下一小步教学。只有用户追问、排查问题、或生成图片/Obsidian资产时，才列具体路径。


## 作者 perspective 索引

作者 skill 不只查目录，还要维护索引：

```text
~/.hermes/learning/authors-index.json
```

字段：

```json
{
  "作者名": {
    "skill": "作者-perspective",
    "books": ["已关联书籍"],
    "domains": ["适合领域"],
    "last_used_at": "YYYY-MM-DD"
  }
}
```

每次加载或新建作者 perspective 后更新索引，避免重复蒸馏同一作者。
