# Economics Textbook Disambiguation Notes

Use when AI 学习法 teaches economics from 微信读书 or local books and the user mentions “经济学原理 / 经济学”.

## Core distinction

- `《经济学原理》` generally refers to N. Gregory Mankiw / 曼昆, *Principles of Economics*.
- Samuelson & Nordhaus wrote `《经济学》`, English title *Economics*.
- Do not call Samuelson/Nordhaus `《经济学》` “经济学原理” unless the source itself uses that title.

## Shared content vs differences

Both are mainstream introductory economics textbooks and cover much of the same core framework:

- scarcity, opportunity cost
- supply/demand, equilibrium, elasticity
- consumer behavior, firm costs, competition/monopoly
- taxation, externalities, public policy
- GDP, inflation, unemployment
- money, fiscal/monetary policy, trade

Theories are not two incompatible systems. The main difference is teaching style and selection:

- Mankiw: more modern, lighter, case-driven, friendly for first-pass beginners.
- Samuelson/Nordhaus: classic comprehensive textbook, broader and more textbook-like; can be slightly heavier.

For this user, if using Samuelson/Nordhaus, teach in a “Mankiw-like” way: concrete, conversational, small steps, business/live-commerce examples.

## WeRead transparency rule

When using WeRead:

1. `/book/info` = book metadata.
2. `/book/chapterinfo` = table of contents / chapter anchors only.
3.正文原文 / highlights / notes require separate capability; do not imply they were read if only chapterinfo was called.

If only chapterinfo was used, say: “这是微信读书目录骨架 + 通用知识蒸馏，不是逐页原文蒸馏。”

## Range rule

For comprehensive textbooks, state scope before teaching:

- exact title and authors
- whether it is micro-only, macro-only, or comprehensive
- current chapter belongs to micro or macro section
- chapter count/source if asked, using live chapterinfo when available

Example from this session: WeRead bookId `3300174856` resolved to Samuelson/Nordhaus `《经济学：第19版》`, 31 main chapters in chapterinfo; chapters 1–18 were micro-leaning and 19–31 macro-leaning in that table of contents. Re-query live data rather than hard-coding if accuracy matters.
